Class ServiceCollectionExtensions

Namespace
Invex.Extensions.Hosting
Assembly
Invex.Extensions.Hosting.dll

Provides extension methods for Microsoft.Extensions.DependencyInjection.IServiceCollection that register a single implementation type under multiple service types ("forwarded" registrations) while sharing one instance per lifetime.

[PublicAPI]
public static class ServiceCollectionExtensions
Inheritance
object
ServiceCollectionExtensions

Examples

// MyService implements both IFoo and IBar; both resolve to the same singleton.
services.AddSingleton<IFoo, IBar, MyService>();

// All three resolve to the same object:
var foo = provider.GetRequiredService<IFoo>();
var bar = provider.GetRequiredService<IBar>();
var service = provider.GetRequiredService<MyService>();

// MyWorker implements IWorkerStatus and IHostedService; the running hosted service
// instance is also resolvable as IWorkerStatus.
services.AddHostedService<IWorkerStatus, MyWorker>();

Remarks

The standard AddSingleton/AddScoped methods create an independent instance per service type when the same implementation is registered multiple times. The overloads in this class instead register the implementation type once and forward each service type to it, so resolving any of the service types yields the same instance (per scope, for scoped registrations). TImplementation itself is also resolvable and returns that same instance. Singleton registrations share one instance for the application lifetime; scoped registrations share one instance within each scope, and different scopes receive different instances.

The AddHostedService overloads additionally register the implementation as an Microsoft.Extensions.Hosting.IHostedService, allowing other components to interact with the running hosted service through its service interfaces.

The container may dispose the shared instance more than once: it tracks every disposable object returned by a factory registration, and each forwarded service type is a factory registration. When the provider (or scope) is disposed, Dispose/DisposeAsync is called once for the TImplementation registration and once for each forwarded registration that was resolved, so implementations should make disposal idempotent.

Registrations are appended unconditionally, like the framework's own AddSingleton and AddScoped methods; they are not conditional TryAdd registrations.

In the net10.0 build, the TImplementation type parameter of every overload is annotated with [DynamicallyAccessedMembers] (DynamicallyAccessedMemberTypes.PublicConstructors), so the constructors required by the dependency injection container are preserved under trimming.

AddHostedService<TService, TImplementation>(IServiceCollection)

Adds a hosted service of the types specified in TService, with an implementation type specified in TImplementation to the specified Microsoft.Extensions.DependencyInjection.IServiceCollection.

public static IServiceCollection AddHostedService<TService, TImplementation>(this IServiceCollection serviceCollection) where TService : class where TImplementation : class, TService, IHostedService
